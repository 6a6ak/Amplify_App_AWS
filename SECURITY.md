# Security maintenance

The existing README and screenshots are intentionally preserved.

## Changes in this patch

- Require verified Cognito access tokens and admin group membership for server mutations, internal diagnostics, and firmware information.
- Reject administrative requests when authentication configuration is missing.
- Limit request size and request rate; allow cross-origin browser access only for configured origins.
- Stop logging GraphQL API keys, request headers, and raw events.
- Generate temporary passwords using cryptographic randomness.
- Remove generated bundles, deployment archives, local Amplify outputs, build logs, and the embedded bare repository from Git tracking. Local copies remain available.
- Update dependencies within the supported package ranges and update the obsolete Vite build dependency.

## Server configuration

Set COGNITO_USER_POOL_ID and COGNITO_CLIENT_ID to the intended Cognito pool and application client. Set COGNITO_ADMIN_GROUP (default: admin) to an existing administrator group. Assign trusted administrators to this group through AWS administration. Ordinary signed-in users must not receive this group automatically.

ALLOWED_ORIGINS is a comma-separated list of exact browser origins when using a separate frontend. Same-origin requests do not need it. Do not put AWS secrets or privileged API keys in VITE_ variables; Vite embeds them in browser assets.

amplify_outputs.json must be generated by the Amplify backend or provided locally before building. It is intentionally not committed.

## Remaining work before claiming production security

- Private device keys and secrets files occurred in Git history. Revoke and replace affected IoT certificates, Wi-Fi passwords, API keys, and any other exposed credentials. Removing files does not revoke credentials or remove GitHub history. This patch does not force-push or rewrite existing branches.
- The Amplify data schema still allows public API-key writes. Converting IoT ingestion functions to role-based signed requests must accompany restricting these rules; changing the rules alone would break ingestion. This cloud migration is deliberately excluded from this limited patch.
- Legacy AWS SDK v2 dependencies remain unsupported and have audit findings. Migrating both servers and Lambda deployments to v3 requires separate integration testing. Do not use audit fix --force to downgrade AWS SDK to v1.
- Public telemetry endpoints currently return full records, including plate/device metadata. Review the intended public fields before production use.
- Live API Gateway authorizers, IAM roles, firmware TLS verification, and deployed cloud configuration have not been verified by these local checks.
- GitHub reported Dependabot alerts and secret scanning disabled. Security alert clearance cannot be verified from this checkout.

Run npm audit in the root, server, and server/aws_lambda directories to review current dependency findings. The frontend build and authorization regression tests do not verify live AWS deployments.

## Validation for this patch

- Six authorization regression tests passed, including mixed-case diagnostic paths.
- Production frontend build passed.
- Root dependency audit: zero reported vulnerabilities after updates.
- Server dependency audit: six findings remain (two moderate, four high); standalone Lambda: two moderate findings.
- Current tracked text scan found no AWS access-key IDs, PEM private keys, or Discord webhook URLs. This limited scan is not a guarantee that no secrets exist.
