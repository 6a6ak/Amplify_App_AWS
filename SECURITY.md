# Security maintenance

README and all screenshots are unchanged from main.

## Implemented

- Administrative server requests require verified Cognito access tokens and admin group membership; missing configuration fails closed.
- Request size/rate limits, exact CORS origins, safe public response fields, cryptographic temporary passwords, and no raw source or secret-bearing logs.
- SDK v3 replaces unsupported SDK v2 in both server and standalone Lambda. Shadow payload decoding preserves v3 byte-array semantics.
- Amplify models no longer accept public API keys. Owners have read access; trusted administrators manage records. IoT functions use IAM grants and the Amplify runtime client instead of shared API keys.
- Telemetry validates input and looks up ownership from the registered device. Typed model operations replace interpolated GraphQL; failed writes throw for retry handling.
- ESP8266 validates server certificates, synchronizes its clock, and retains certificate objects for reconnects. Insecure TLS bypasses are removed.
- Generated deployment archives, local outputs, logs, credential material, and embedded Git backups are excluded from tracking.
- The browser imports only public Cognito identifiers from src/amplify-auth.json. Generated data API keys are not bundled. Update those public identifiers when deploying a replacement user pool.
- Deployment templates use Node 22; frontend build configuration selects the current Node 22 release and uses npm ci. Local backend tooling requires Node >=22.15.
- GitHub Dependabot alerts, secret scanning, and secret push protection were enabled.

## Deployment

Set COGNITO_USER_POOL_ID and COGNITO_CLIENT_ID to the intended pool and app client. Set COGNITO_ADMIN_GROUP to the trusted group (default admin). Assign trusted users to that group through AWS administration. ALLOWED_ORIGINS is an optional comma-separated list of exact origins for a separate frontend. Never place privileged credentials in VITE_ variables.

Deploy the Amplify schema and ingestion functions together: IAM grants and runtime data configuration are generated by the backend deployment. Existing unregistered devices must be registered by an administrator with the correct owner before telemetry ingestion. The frontend build does not deploy the backend. Deploy updated Lambda artifacts/templates and flash updated firmware to apply their protections.
